# C1 최종 품질 검토

2026-11-13 · 범위: 소스 실행 C1 재검수 기능 · **판정: C1 기능 품질 검증 완료**

자료 변경 후 재검수, 현재 내용에 묶인 승인 보호, 본문 보존·복원·비동기 상태 일치를 검증했다. 합성 자료를 사용한 실제 HWP COM E2E·수용·회귀가 통과했으며, 확인한 범위에서 승인 우회·기존 파일 덮어쓰기·본문 유실과 같은 치명적 결함은 발견되지 않았다. 이는 정식 배포 완료나 모든 상용 환경에서의 무결함 보장이 아니다.

## 완료 기준과 근거

동일 16개 합성 시나리오를 3회 반복한 48회 지표와 실제 COM 파일 시험을 별도로 집계했다. AI 응답·키 저장소·테스트용 대화상자 응답은 모의했지만, 실제 exporter 저장과 한글 COM은 대역으로 바꾸지 않았다. 파일 접근 보안 승인은 사용자가 직접 수행했으며 자동 승인·보안 우회는 하지 않았다.

## 수정한 결함

저장 성공 직후 아무 입력도 바꾸지 않고 같은 이름으로 재저장해 실패하면 이전 성공 표시가 남았다. 실제 UI 시험에서 수정 전 실패를 재현했고, 새 승인 시도 때 성공 표시·파일 열기 버튼을 해제하도록 수정했다. 본문과 마지막 성공 경로는 보존하며 성공 응답 때만 다시 성공으로 표시한다. 추가 회귀 검사로 25개에서 26개가 됐다.

Python 3.12/PDF 라이브러리의 첫 OS 조회가 시험 중 subprocess 금지 경계에 걸리는 준비 문제도 수정했다. OS 조회를 준비 단계로 옮겼으며 제품 승인 보호·동일 입력/분모·실패 판정은 완화하지 않았다.

## Open 43초·119.8초의 해석 정정

해당 시간은 COM Open 호출 시작부터 반환까지이며 **사용자가 한글 파일 접근 승인을 누르기까지의 대기**를 포함한다. 사용자가 늦은 승인으로 발생한 시간이라고 확인했다. 순수 프로그램 처리시간을 분리 측정하지 않았으므로 성능 결함·처리시간 개선·SLA의 근거로 사용하지 않는다.

추가 관찰 첫 회차는 전체 실행 120초에 외부 감시기가 먼저 미완료를 기록했고, 자식 시험은 나중에 파일 4개를 모두 열고 정상 종료했다. 이 회차를 소급해 PASS로 바꾸지 않았다. 같은 기준·새 폴더의 후속 3회/12 Open은 모두 PASS였다. 승인 대기를 없애기 위한 자동 보안 승인이나 기준 완화는 하지 않았다.

## 별도 범위·남은 출시 게이트

- 배포 EXE·설치 패키지의 C1 검증 및 정식 릴리스: 미실행.
- 기존 업무 문서가 열린 한글과의 동시 실행, 전용 VM/독립 계정, 여러 한글 버전: 미검증. 이번에는 기존 한글이 없는 상태에서 새 객체의 HWND/PID를 확인했다.
- 실제 COM 강제 멈춤·안전 복구·완료 불명 재시도: 미검증이며 C2 범위. exporter에 새 timeout/자동 복구를 추가하지 않았다.
- 실제 AI 응답 품질·운영 사고율·실사용 검수시간·만족도: 이번 시험에서 미측정.
- 탐색기 더블클릭 파일 연결: 별도 미검증. 실제 COM Open과 구분한다.

**정식 배포·main 병합은 PM 승인 대기**다. 기능 개발·정의한 E2E·품질 검증 완료와 배포/상용 안정성 검증 완료를 분리한다.
