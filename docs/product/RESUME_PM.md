# PM 이력서 반영 문구

기존 3페이지 이력서의 대표 프로젝트 항목에 선택해 넣을 문안이다. 이력서 원본은 제공받지 않아 직접 편집하지 않았다. 회사명·기간·직책·연락처를 임의 작성하지 않는다. 아래 7문장을 모두 넣어 분량을 늘리기보다 지원 직무에 맞춰 5~7개를 사용한다.

## 대표 프로젝트 제목과 역할

**AI 현장점검 결과서 자동화 — 업무 자동화 및 승인 품질 개선**

역할: 업무 문제·MVP·우선순위·수용 기준·검수·출시 판단. Codex의 분석·구현·테스트 지원 활용. 상태: 기존 v0.4.26 배포 이력 / C1 로컬 합성 검증 승인, 정식 출시 보류.

## 우선 제안: 핵심 문장 7개

1. 사업계획서·회의록 확인부터 기존 HWP 양식 작성까지의 반복 업무를 분석하고, 자료 입력→초안→검토·수정→승인 저장을 MVP로 정의했다.
2. 초기 실제 업무에 직접 3건 이상 적용해 평균 약 60분→3분, 약 95% 작성 시간 단축을 경험했다. 초기 개인 적용 기준이며 건별 시간 원기록은 없다.
3. 소스·기존 검사를 대조해 자료 변경 후 이전 본문이 승인 경로에 도달하는 공백을 정의하고, 재검수·수정 차이 확인·저장 복구를 영향도·시급성·개발 부담으로 비교했다.
4. C1 재검수를 영향도 5·시급성 4·개발 부담 3으로 우선 선정하고, PRD의 14개 수용 기준과 5개 MVP 범위로 구현·회귀 검증 대상을 고정했다.
5. 위험 차단과 정상 흐름 보존을 함께 측정하도록 KPI를 정의하고, 동일한 합성 시나리오 16개를 3회 반복한 48회 시험에서 미검토 저장 진입 18/18→0/18건, 정상 저장 오차단 0/30건 유지를 확인했다.
6. 신규 수용 검사 25개·기존 GUI QA 4개 통과를 검토하고, 기존 단위 검사 151개 중 147개 통과·Windows 설치 COM 4개 제외 및 AC14 실연동 미검증을 결과에 명시했다.
7. 합성 통과와 출시 가능 여부를 분리해 C1 정식 출시·병합을 보류하고, 전용 Windows 환경·프로세스 격리·실제 HWP 저장 및 재열기 검증을 출시 전 조건으로 정리했다.

2번은 초기 도구의 업무 적용 성과이고 5~7번은 C1 개선 경험이다. C1으로 업무시간이 95% 줄었다거나 실제 혼재 사고가 100% 감소했다고 연결하지 않는다. 분량을 줄이더라도 “합성”, “개인 적용”, “출시 보류”를 삭제하지 않는다.

## 1분 설명 예시

> 현장점검 후 자료를 확인하고 한글 결과서를 만드는 반복 업무를 자동화했습니다. 초기 개인 적용에서 3건 이상 사용해 약 60분이던 작업이 약 3분으로 줄었지만, 건별 측정 기록이 없는 경험치로 구분합니다. 이후 제품 흐름을 분석하면서 자료를 바꾼 뒤 이전 본문을 그대로 승인할 수 있는 공백을 찾았습니다. 세 과제를 비교해 재검수를 먼저 선택하고, 14개 수용 기준과 정상 저장 오차단 지표까지 정의했습니다. Codex 지원으로 구현·검증한 결과 동일한 합성 48회 시험에서 미검토 저장 진입은 18/18에서 0/18로 줄고 정상 오차단은 0/30을 유지했습니다. 실제 한글 저장 검증이 남아 출시를 보류한 상태입니다.

## 사용하지 않을 표현

- “운영 사고 100% 제거”, “AI 정확도 100%”, “사용자 만족도 개선”: 측정하지 않았다.
- “C1 도입으로 업무시간 95% 절감”: 초기 자동화 개인 경험과 C1 결과를 혼합한다.
- “151개 회귀 전부 재통과”, “실제 HWP 검증·배포 완료”: 현재 제외·미검증 범위와 다르다.
- “스쿼드 리딩”, “매출 성장”, “A/B 테스트”, “대규모 사용자 검증”: 수행 근거가 없다.
- “독립적으로 모든 코드를 개발”: Codex 지원 범위를 숨기는 표현이다.

이력서에는 실제 공개된 문서 URL을 확인해 사용한다. 초기 개인 경험·합성 검증·미검증 범위를 축소해 표현하지 않는다. [공개 범위](RELEASE_REVIEW_PUBLIC.md#공개-범위와-개인정보)를 따른다.
