18/30의 지표는 저장 함수 진입 경계를 관측하며 API·저장은 대역이다. 실제 COM 파일 시험을 그 48회에 합산하지 않았다. 입력은 모두 합성이고 실제 회사 문서·개인정보·키·NAS를 사용하지 않았다. 수치는 운영 사고 감소율·사용자 만족도·AI 정확도가 아니다.

## AC와 X 분기

AC01~AC13은 합성 수용 검증 통과. AC14는 미검토 I/O 차단·실패 보존 모의 회귀에 더해 실제 COM 정상 저장·동명 보호·장문·재입력/파일 Open·내용/서식을 확인했다. 모든 AC를 실제 AI 호출로 검증했다는 뜻이 아니다. X01~X08은 부분 수정, 지연 응답, 명시 검토/편집, 필수값, 초기화, 복원, 자료 식별, 저장 보호의 분기 그룹으로 수용 검사에 포함하며 18/30 분모와 구분한다.

## 실패·중단 기록은 유지

| 기록 | 판정·후속 조치 |
| --- | --- |
| 원래 workflow fixture 연도·분과 누락 | 기존 FAIL 보존. 필수 fixture 2줄을 별도 커밋으로 정비하고 보호 조건은 유지 |
| 수용/비교 실행기의 OS 조회 경계 위반 | 개별 assertions가 통과해도 회차는 무효. 준비 단계에서 OS 조회 후 같은 기준으로 재시험 |
| 재저장 실패 시 성공 표시 잔류 | 수정 전 신규 검사 FAIL, UI 수정 후 26/26 PASS |
| 네이티브 단위 최초 1건 CMD timeout | 최초 150 PASS·1 ERROR 유지. 20초 기준 변경 없이 후속 151/151 PASS |
| 초기 화면 관찰자 timeout·COM Open 중단 | 미완료 유지. 별도 재열기·전체 렌더 및 후속 Open 통과로 구분 |
| 추가 Open 관찰 첫 회차 120초 감시기 종료 | 감시 회차는 미완료, 자식은 나중에 4 Open 완료. 후속 새 회차 3×4 PASS |

Open 호출 시간에는 **사용자의 한글 파일 접근 승인 대기**가 포함됐다. 사용자가 지연 사유를 확인했으며 이를 처리 성능 문제나 성능 개선으로 표현하지 않는다. 승인 대기와 실제 처리시간을 분리한 측정은 하지 않았다.

기존 원시 증거 57개 SHA-256 일치를 확인했고 기존 Baseline·실패·새 로그는 로컬에 보존했다. 원시 로그·HWP·호스트 경로·PID·기존 로컬 Git 이력은 공개하지 않는다. 공개 요약·합성 fixture·재현 코드·안전한 렌더 이미지로 근거를 연결한다.
