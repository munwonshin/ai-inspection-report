# C1 사용성 테스트·KPI 측정 계획 — 공개본

> **상태:** 실행 전 계획. 아래 목표·지표·실험 설계는 **아직 실시하지 않은 사용성 평가**이며 실제 사용자 행동 데이터, 퍼널 수치, 만족도 결과를 의미하지 않는다. 기존 48회 합성 검증 및 HWP E2E는 [품질 검증](QUALITY_REVIEW.md)에 별도 기록돼 있다.

## 1. 검증 질문과 가설

- **Q1:** 사용자가 B 자료로 변경된 후 재검수가 필요하다는 사실을 스스로 인지하는가?
- **Q2:** 차단 안내를 본 뒤 다음 행동(대조·수정·검토 완료)을 이해하는가?
- **Q3:** C1이 잘못된 저장을 막으면서 정상 작업에 과도한 추가 시간을 요구하지 않는가?
- **Q4:** 실제 배포 환경에서 승인 후 HWP 저장·재열기가 정상 완료되는가? (배포 EXE 검증과 별도 게이트)

가설: 명시 검토 안내는 오류 위험을 낮추되 정상 작업 완료에 불필요한 방해를 주지 않을 것이다. **사용자 효과는 미검증**.

## 2. 사용자 테스트 계획 (미실행)

**대상:** 현장점검 결과서 작성 경험이 있는 실무자. 모집·참가자 수·일정 미정. 진행 전 사내 자료 취급·참여 동의를 확인하고 합성 자료만 사용한다.

**과제 T01:** A 초안 작성 후 B로 변경하고, 안내 문구를 보자마자 이해한 행동을 말한다.

**과제 T02:** B 자료로 수정·명시 검토하고 저장을 완료한다. 기존 본문이 삭제되지 않아야 한다.

**과제 T03:** 검토 전 승인 시도와 검토 후 정상 저장을 각각 수행한다. 사용자에게 우회 방법을 미리 알려주지 않는다.

**기록:** 과제 성공/실패, 사용자 질문·혼동 지점, 최초 안내 인지 여부, 대조 시작~승인 준비의 **활성 검수시간**, 정상 저장 완료 여부. 사용자 식별정보·실제 회사 문서·API 키 수집 금지.

## 3. KPI 사전 정의

| 지표 | 산식 / 기록 방법 | 근거 상태 |
| --- | --- | --- |
| 미검토 저장 진입률 | 미검토 상태에서 저장 함수 진입한 시도 ÷ 유효 미검토 시도 | 합성 18/18→0/18 확인, 실제 운영률 아님 |
| 정상 저장 오차단률 | 정상인데 저장 함수에 진입 못한 시도 ÷ 유효 정상 시도 | 합성 0/30 유지 |
| 재검수 안내 이해율 | 차단 뒤 추가 설명 없이 다음 행동을 정확히 말한 사용자 ÷ 안내를 본 사용자 | **미측정** |
| 재검수 과제 완료율 | 지정된 재검수·승인 흐름을 완료한 사용자 ÷ 과제를 시작한 사용자 | **미측정** |
| 활성 검수시간 | B 변경 후 대조 시작~승인 준비, 외부 대기/중단 제외 | **미측정** |
| 실제 HWP 저장 성공률 | 성공적으로 저장·재열기 확인된 시도 ÷ 실제 저장 시도 | 합성 E2E 샘플은 존재, 운영 성공률 **미측정** |
| 사용자 만족도 | 동일 문항 5점 척도 및 자유 응답, 표본수 병기 | **미측정** |

**퍼널 제안:** B 자료 첨부 → 재검수 안내 인지 → 본문 대조/수정 → 명시 검토 완료 → 저장 성공. 단계별 진입 건수와 전환율은 실제 관찰 후에만 기재한다. 샘플이 작다면 통계적 유의성이나 제품 전체 효과로 일반화하지 않는다.

## 4. 판정 규칙과 후속 조치

- **PASS/FAIL/미검증**을 각 테스트 과제와 지표에 구분해 기록한다.
- 안내를 이해하지 못하면 사용자 문구·화면 배치를 개선 가설로 올리고 재시험한다.
- 재검수 시간이 크게 늘어났다면 안내·화면 이동·불필요한 재검수 조건을 관찰하고 C3와 우선순위를 재평가한다.
- 정상 저장이 실패한다면 환경·문서 조건을 기록하고 C2 조사 또는 배포 게이트로 연결한다.
- 실제 관측 데이터가 없으면 목표치·향상률을 사후에 만들어 넣지 않는다. 출시 판단은 [출시 검토](RELEASE_REVIEW_PUBLIC.md)와 구분한다.
