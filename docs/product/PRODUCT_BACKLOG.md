# C1 제품 백로그·협업 기준 — 공개본

> **상태:** 기존 PRD·품질 검증을 기준으로 작성한 요구사항 추적용 백로그. 협업 도구에서 운영한 실제 스프린트 기록이나 개발팀 회의록으로 주장하지 않는다. 작업 일수·담당자 조직을 임의로 만들지 않았다.

## 우선순위 기준

P0 = 잘못된 결과 확정이나 작업물 손실 위험이 직접 존재, P1 = 검토 부담·안내 개선, P2 = 별도 근거 확보 후 범위 확정. '완료'는 C1 소스 기능 및 정의된 시험 범위의 완료이며 배포를 뜻하지 않는다.

## 협업·전달 기준

- **기획 입력:** 사용자 문제, 영향 범위, 예상 동작, 제외 범위 및 위험을 [PRD](PRD_PUBLIC.md)에 고정한다.
- **디자인 입력:** 상태·메시지·화면 전이를 [UX 명세](UX_PROTOTYPE_SPEC.md)에 연결한다. 실제 Figma 산출물은 아직 없다.
- **개발 검토:** Codex의 분석·구현 지원을 활용하며, 직접 개발팀 스프린트를 운영했다고 표현하지 않는다.
- **QA 인수:** 성공 사례뿐 아니라 정상 저장 오차단과 실패·복원·기존 파일 보호를 검사한다. [품질 근거](QUALITY_REVIEW.md).
- **출시 판단:** 소스 품질 검증과 배포 EXE 검증을 분리한다. 2026-11-16 사용자 승인에 따라 실제 EXE 검증 후 main 병합·정식 배포 완료. [배포 근거](EXE_RELEASE_REVIEW.md)
- **변경 관리:** 범위 밖 개선(C2·C3)은 C1에 묶어 개발하지 않고 별도 요구·우선순위 재평가한다.

## 이후 실제 운영할 때 기록할 필드

백로그 ID, 사용자 가치, 완료 조건, 우선순위 근거, 담당자(실제 배정 시), 상태, 발견 결함, 완료 근거 링크, 출시 여부. 아직 없는 담당자·스프린트·예정 일정을 작성하지 않는다.
