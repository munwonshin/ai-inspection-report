# 접근 확인 없는 한글 저장·문단 사이 빈 줄 3pt · 0.4.2

검사일: 2026-10-22. Windows 11/한글 2018에서 명확한 가상 자료만 사용했다.

## 최종 동작

사용자가 승인한 후, 양식을 채운 HWPML을 한글 문자열 API SetTextFile로 전달한다. BSTR은 UTF-16이므로 XML 선언도 UTF-16으로 맞춘다. UTF-8 선언을 그대로 넘기면 이 환경에서는 XML 코드가 보이는 일반 텍스트로 들어갔으므로, 여섯 표와 각 칸 내용을 즉시 검사해 잘못된 변환을 차단한다.

한글 GetTextFile(‘HWP’)에서 받은 Base64 데이터를 복원해 진짜 CFB HWP 헤더를 검사하고, 프로그램이 선택 경로의 승인 후 임시 영역에 기록한다. 기록된 바이트를 다시 읽어 일치를 검사한 뒤 한글에 HWP 형식으로 다시 입력하고 표·본문·일반현황·서명 칸·3pt 설정을 재검증한다. 검증 후 최종 이름으로 이동하며 자동 덮어쓰지 않는다.

한글의 파일 Open/SaveAs 호출과 파일 접근 승인 모듈은 사용하지 않는다. 이 PC의 실제 시험에서는 접근 허용 클릭 없이 완료했다. 최종 프로그램은 한글 보안 설정·레지스트리를 바꾸거나 별도 보안 DLL을 설치하지 않는다. 문자열 API 내부에서 한글 자체가 임시 파일을 사용하는 부분은 한컴 구현에 따르며, ‘디스크 I/O가 전혀 없다’는 의미는 아니다. 앱은 승인 전 결과 HWP/선택 경로의 임시 결과를 만들지 않는다.

새 AI 문단은 ‘• ’처럼 글머리표 뒤 공백 한 칸을 넣고 주제가 다른 문단 사이는 빈 줄 하나로 구분하도록 했다. 빈 줄만 별도 문단 모양을 복제하여 Fixed/300 HWPUNIT(3pt), 문단 위·아래 간격 0, 격자 맞춤 해제로 설정한다. 본문 글자·글자 크기·기존 본문 줄간격은 유지한다. 기존 표·일반현황·제목의 문단 모양은 바꾸지 않는다. 사용자 직접 편집 내용에 임의 빈 줄·글머리표·공백을 추가하거나 문장을 고쳐 쓰지 않는다. 직접 편집 시에도 원하면 문단 사이에 빈 줄 하나를 넣으면 그 빈 줄에 3pt가 적용된다.

## 확인한 결과

- 단위검사 57개 통과. 승인 전에 COM/파일 접근이 시작되지 않음, 일반 본문과 빈 줄의 서로 다른 스타일, 빈 줄 3pt 변조 감지, 잘못된 HWP 데이터 거부, Base64 줄바꿈 수용, Open/SaveAs/RegisterModule 미호출을 포함한다. 모의 전송 검사와 실제 한글 시험은 구분했다.
- 소스 앱 경로에서 가상 HWP 두 건을 접근 허용 클릭 없이 저장하고 실제 디스크의 데이터를 한글에 다시 입력했다. 여섯 표·각 칸의 편집 내용·서명 칸과 빈 줄 Fixed/300이 일치했다. 각각 한 페이지였다.
- 90개 가상 장문 문단은 세 페이지로 저장되고 마지막까지 본문·3pt 설정이 일치했다. 실제 같은 이름 충돌은 저장 전에 거절됐고 기존 파일 SHA256이 유지됐다.
- 가상 자료로 실제 AI 1회 수행. 글머리표 뒤 공백·문단 사이 빈 줄과 회의록 중심 내용을 확인하고 결과를 실제 HWP로 저장·다시 입력했다. 실제 업무 예시 PDF·회의록은 API에 보내지 않았다.
- 최종 frozen EXE 자체의 --hwp-worker로도 가상 HWP를 저장·다시 입력했다. 추가 UI 클릭 없이 성공했고 진짜 CFB HWP 형식이었다. 총 실제 HWP 저장 시험은 5건이다. 최종 코드 10개 모듈과 소스 컴파일 결과도 일치했다.
- Tk 점진 표시·승인 잠금·오류 보존·버퍼 해제 및 저장 이름 정리/차단/충돌 후 보존 회귀검사 통과. 승인한 최신 스냅샷을 전달하는 구조는 유지했다.
- 별도 검증용 한글 창에 저장 데이터를 실제로 표시했지만 Windows 화면 검수 도구가 두 번 모두 ‘computer-use request timed out: list_windows’로 실패했다. 따라서 화면 캡처를 통한 표·페이지 육안 검수와 일반 파일 열기 메뉴로 재열기를 완료했다고 표시하지 않는다. 문자열 API 재입력 후 HWPML의 내용/서식 일치 검증은 실제로 통과했다.
- 다른 한글 버전·다른 PC·실물 NAS 시험은 미실시. Windows 탐색기에서 접근 가능한 UNC/매핑 경로 지원 및 오류 시 입력 보존 구조를 유지했다. 업무 3시간→10분 단축은 여전히 실측 전 목표다.

## 보안 모듈 조사 기록

처음 고려한 한컴 예제 모듈은 모든 파일 접근을 허용하는 영구 등록 방식이라 자동 승인 검토에서 거절되어 설치·등록하지 않았다. 승인 경로/PID만 허용하는 작업 제한 모듈도 조사했으나 이 한글에서 RegisterModule이 False여서 배포에 포함하지 않았다. 해당 진단용 임시 등록값은 모두 정리됐고, 최종 소스·배포에는 해당 DLL/코드/컴파일러가 없다. 최종 문자열 API 방식은 보안 설정 변경 없이 시험을 통과했다.
