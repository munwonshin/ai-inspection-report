# 0.4.15 채팅 수정·정확 복원 검증

검증일: 2026-10-27

## 수정
- 이전 초안 본문을 불변 Report 스냅샷으로 메모리에 보관합니다. '방금 수정하기 전으로 되돌려 주세요' 같은 복원 요청은 API 재생성 없이 해당 버전의 본문을 로컬에서 복원합니다. 직접 편집한 문장도 포함합니다. 제목·일반현황·저장 경로는 현재 값으로 유지하며, 복원 자체는 파일을 생성하지 않습니다. 앱 종료 시 초안 이력은 사라집니다.
- 근거가 없어 반영할 수 없는 요청을 구조화한 decision/notice로 구분합니다. blocked 응답은 반환 본문과 관계없이 기존 초안 전체를 유지하며, 대화와 상태 영역에 짧은 사유를 표시합니다. 수정 요청 입력도 남겨 다시 고칠 수 있습니다.
- 수정 범위 밖 항목 및 가상 표시·검수 메모의 변경을 검사합니다. 의도하지 않은 변경이 감지되면 새 응답을 적용하지 않고 원문을 유지합니다. 검수 메모 삭제·문체 변경처럼 명시적으로 요청한 변경은 허용합니다. 모든 자연어 요청의 의도를 완벽하게 해석한다는 보장은 아닙니다.

## 검증
- 90개 단위 검사 통과(기존 79개 + 복원/부분 범위/표시 보존 검사 11개).
- 같은 가상 PDF·회의록·직접 편집 초안으로 실제 스트리밍 API 수정 8종×2회=16회 통과. 향후 항목만 수정, 문체 변경, 지정 문단 삭제, 메모 원문 보존, 한 문장 정리, 번호 변경·첨부 지시문 무시, 근거 없는 성과 차단, 두 곳 동시 수정을 확인했습니다.
- 실제 Tk 앱 로직과 실제 API로 수정 후 로컬 복원 흐름을 2회 통과했습니다. 복원 순간에는 API 호출과 보안 저장소 읽기를 금지한 상태에서도 원문 스냅샷과 정확히 일치했습니다.
- 실제 Tk에서 실제 API의 근거 없는 성과 요청을 한 번 더 시험하여 기존 초안 완전 보존·미반영 사유 표시·수정 입력 유지·저장 함수 미호출을 확인했습니다. 총 실제 AI 요청은 위 16회+Tk 3회=19회입니다.
- 기존 workflow/chat/stream/response_failure Tk 회귀 검사 통과. 회귀의 네트워크는 모의 응답으로 통제하며 실제 API 시험과 구분합니다.

API 키·업무 자료는 시험 및 배포 자료에 포함하지 않습니다. 기존 모델과 HWP 저장 모듈은 유지합니다. NAS 실장비 및 다른 PC·한글 버전은 이번에 검증하지 않았습니다. 소수 가상 사례의 통과를 보편적인 정확도나 업무시간 단축 성과로 표시하지 않습니다.

독립 실행형 qa/revision_checks.py로 추가 3회 실제 API 요청을 수행하여 외부 검증 파일 없이도 같은 복원·미반영 안내 결과를 확인했습니다. 따라서 이번 수정 검증의 본문 API 요청은 총 22회이며, 최종 EXE의 별도 짧은 연결 확인 요청은 이 수에 포함하지 않습니다.

최종 EXE 검증: 15개 모듈 소스 일치, 컴파일된 복원·거절 응답 원문 보존, 실제 API 연결·TLS 검증 유지, 가상 HWP 생성 및 저장 바이트 재입력 검증 통과(1쪽).
