# 0.4.18 초기화 검증

검증일: 2026-11-02. Windows 11, 실제 Tk 위젯, 격리된 가상 사용자 설정과 가상 파일을 사용했습니다. 실제 API 키나 업무자료를 읽거나 변경하지 않았습니다.

## 동작

상단 ‘초기화’를 한 번 누르면 첨부 PDF/HWP의 메모리 자료, 회의록, 초안·채팅·수정/복원·실행취소 이력, 일반현황, 사업연도·분과, 저장 파일명·경로, 저장 완료 연결을 처음 상태로 되돌립니다. 고정한 점검자 소속·점검자와 고정 체크도 해제하고 사용자 설정에 반영합니다.

API 키·모델·연결 상태는 유지합니다. 초기화 메서드에서는 보안 저장소와 API를 호출하지 않습니다. 원본 첨부 및 이미 저장한 결과 파일은 삭제하지 않습니다. 작성·변환·저장 중에는 버튼을 비활성화하고 직접 호출도 거부하여 진행 중인 작업과 충돌하지 않게 합니다.

고정 설정을 초기화하는 쓰기에 실패하면 작업 내용을 비우기 전에 오류를 알리고 기존 입력을 보존합니다. 정상 초기화는 별도 확인 창 없이 한 번의 클릭으로 실행됩니다.

## 확인 결과

- 단위검사 105개 통과: 기존 103개 및 처리 중 초기화/설정 쓰기 실패 경계 2개.
- 실제 버튼 invoke 한 번으로 첨부 자료·본문·요청·일반현황·연도/분과·저장 경로·이력을 제거하고 시작 화면으로 복귀.
- API 연결 상태 True/False 모두 초기화 전후 동일. vault.read/save/delete, API 연결/생성, HWP 저장 호출은 모두 0회. 실제 키 값에 접근하지 않았습니다.
- Tk 편집 실행취소로 삭제 전 내용이 복원되지 않음을 확인. 늦게 실행되는 고정 설정 타이머가 옛 값을 다시 저장하지 않는 것도 확인.
- 앱을 새로 만들어도 고정 정보와 체크가 비어 있는 것을 확인.
- 첨부 원본과 기존 결과 파일의 바이트 보존. 초기화 후 새 자료·새 초안 입력과 이력 생성 가능.
- 처리 중 버튼 비활성/직접 호출 차단, 설정 저장 실패 시 기존 회의록 유지.

관련 검사: tests/test_reset.py, qa/reset_checks.py. 다른 PC·한글 버전·실제 NAS 검증을 추가 수행한 결과는 아닙니다.

최종 배포 EXE의 16개 모듈이 저장된 소스와 일치함을 확인했습니다. 실제 사용자 API 키를 이용한 초기화나 실제 업무 입력의 삭제 시험은 수행하지 않았습니다.
