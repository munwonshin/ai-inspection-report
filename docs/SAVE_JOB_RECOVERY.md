# HWP 저장 작업 감독과 UI 모듈 경계 — v0.4.28

## 변경 이유와 범위

기존 저장 호출은 자식 Python 프로세스를 제한 없이 기다렸다. 이제 `save_job`이 작업 수명을 제한하고, 실패가 UI 큐로 돌아오면 편집물과 검토 상태를 유지한 채 잠금을 해제한다. 화면·버튼·C1 검수 계약은 유지한다.

| 모듈 | 책임 |
| --- | --- |
| [exporter](../inspection/exporter.py) | 승인·필수값 검사, HWP 변환·재입력 검증, 부모의 최종 게시 |
| [save_job](../inspection/save_job.py) | 자식 작업 제한 시간, 응답 수신, 실패 정리 |
| [hwp_process](../inspection/hwp_process.py) | 작업 전 PID 목록·프로세스 생성 시각·창 핸들로 신규 COM 소유권 확인, 동일 프로세스 핸들만 종료 |
| [async_tasks](../inspection/async_tasks.py) | 기존 background/poll·작업 세대·스트리밍 완료 큐 처리 |
| [save_flow](../inspection/save_flow.py) | 기존 승인 입력 검사·현재 검수 토큰·불변 스냅샷·성공/실패 표시 |
| [ui](../inspection/ui.py) | 화면과 편집/자료 상태를 유지하며 위 메서드를 상속해 호출 |

비동기·저장 메서드는 기존 호출명과 실제 버튼 연결을 유지하는 작은 mixin으로 분리했다. API·문서 입력·편집 화면을 전면 재구성하지 않았다.

## 저장·시간 초과·재시도

1. 명시 승인과 C1 검토, 필수 입력·경로·동명 검사를 통과한다. 승인 전에는 작업 파일을 만들지 않는다.
2. 부모가 대상 폴더에 새 숨김 임시파일을 만들고 파일 식별자를 기억한다. 기존 파일은 열거나 덮어쓰지 않는다.
3. 자식이 COM을 생성한 뒤 창 PID가 작업 전 목록에 없고 생성 시각도 이번 활성화 이후인지 확인한다. 확인 전에는 문서 변경·Clear·Quit을 호출하지 않는다.
4. HWP 변환 → 내용 검증 → 디스크 쓰기·동기화 → 실제 기록 바이트 재입력 → 내용/서식 검증을 수행한다.
5. 자식 정상 종료·유효한 완료 응답·페이지 수·재열기 확인·임시파일 식별자·SHA-256이 맞을 때만 부모가 no-replace 이름 변경으로 게시한다. 다른 프로세스가 먼저 같은 이름을 만들면 저장하지 않는다.
6. 기본 자식 대기 제한은 **120초**다. 시간 초과 시 Python 작업을 먼저 중단해 늦은 게시를 막고, 기록된 PID·생성 시각·이미지명이 현재 핸들과 모두 같은 신규 작업 한글만 정리한다. 전체 Hwp.exe 종료나 프로세스 트리 일괄 종료는 하지 않는다.
7. 소유한 임시파일만 정리하고 실패를 UI로 전달한다. 본문·기존 결과·마지막 성공 경로는 유지하고 현재 저장 성공 표시는 해제한다. 수정하지 않았다면 기존 유효 검토로 재시도할 수 있으며, 입력이 바뀌면 다시 검토해야 한다.

시간 초과는 작업 대기 제한이며 모든 파일시스템·OS 호출의 엄격한 전체 실행 기한은 아니다. 자식 종료와 한글 종료 확인에는 각각 최대 5초가 추가될 수 있다. 이름 변경의 기존 짧은 잠금 재시도도 유지한다.

**소유권을 확인하지 못하면 추정해서 한글을 종료하지 않는다.** 특히 DispatchEx 내부에서 멈춰 창 소유권을 기록하지 못하면 Python 작업만 중단하고 한글 창 확인 안내를 표시한다. 자동 정리 실패·권한 부족·공유 한글 프로세스인 경우 사용자가 해당 창을 확인해야 한다. 기존 사용자 한글이 COM 객체와 같은 프로세스라면 문서 변경을 거절한다. 모든 한글 버전·세션 공존을 보장하지 않는다.

한글의 파일 접근 확인은 사용자가 직접 승인한다. 승인 대기도 제한 시간에 포함될 수 있으며, 보안 승인을 자동화하지 않는다. 작업 중 생성되는 승인 자료 전달 JSON은 임시 작업 폴더에서만 사용하고 완료/오류 시 정리한다. 문서 원문·API 키를 새 영구 로그나 원격 계측에 기록하지 않는다. OS/권한으로 임시 정리가 거절되면 수동 확인이 필요할 수 있다.

## PDF 호환성

[pdf_layout](../inspection/pdf_layout.py)은 pypdf 버전을 **먼저** 확인한다. 고정 버전 6.10.0일 때만 내부 최적화 모듈을 불러오며, 모듈·함수 누락 또는 호환되지 않는 시그니처이면 공개 `PageObject.extract_text`와 `get_contents`를 사용한다. 구형 공개 시그니처는 일반 추출로 대체한다. 읽을 수 없는 PDF 오류를 빈 성공으로 숨기거나 텍스트를 자르지 않는다. 임의의 모든 pypdf 버전 지원을 보장하지는 않는다.
