# 0.4.12 API 연결 오류 수정

## 원인과 수정

실제 0.4.11 화면의 자동 연결과 API 설정 ‘연결 확인’ 버튼에서 사용자가 보고한 오류를 재현했다. 같은 Windows 계정의 같은 키를 사용한 소스 실행은 성공했지만 EXE에서는 키 인증 요청 전 SSLContext 생성 시 FileNotFoundError(errno 2)가 발생했다.

빌드에 사용한 Python의 ssl.py는 기본 SSLContext 생성 시 공개 인증서 거부 정책인 codex-rejected-cas.pem을 같은 폴더에서 읽도록 구성되어 있었다. PyInstaller가 이 보조 파일을 자동 수집하지 않아 EXE가 해당 파일을 찾지 못했다. Python DLL/TLS 라이브러리와 Windows CA/ROOT 저장소 열거는 정상임을 최소 시험으로 분리 확인했다. 이전 런타임 점검은 TLS 버전 문자열 로딩까지 검사하여 이 누락을 잡지 못했다.

hooks/hook-ssl.py에서 빌드 Python 옆에 이 선택적 파일이 존재하면 변경 없이 frozen ssl 모듈 옆에 포함한다. 일반 Python처럼 이 파일을 사용하지 않는 배포에서는 추가 데이터가 필요 없다. 정책을 삭제/변경하거나 인증서 검증을 우회하지 않는다. Windows 인증서 저장소·방화벽·보안 설정을 바꾸지 않았다.

누락 파일은 906바이트의 공개 TRUSTED CERTIFICATE 정책이며 PRIVATE KEY가 없다. 원본 SHA256: c916ce1b14ed8ca69e9b5c9fab22799a900dd610d6d4ec9b1347f4fd48e53718. 시험 EXE에서 이 파일 하나만 추가하자 SSLContext 생성과 API 연결(약 2.95초)이 성공하여 원인·해결의 인과관계를 확인했다. 최종 배포는 수작업 파일 복사 대신 훅을 적용한 깨끗한 재빌드다.

## 오류 처리 보완

기존에는 시간 초과·DNS·인증서·연결 초기화·로컬 파일 누락을 모두 ‘연결이 끊겼거나 응답 시간이 초과’로 표시했다. 이제 원인별 안전한 안내를 표시하며 원본 예외·프록시 주소·응답 본문·키를 노출하지 않는다.

짧은 OK 연결 시험만 요청별 30초 대기/최대 2회(일시 통신 오류 시 1초 후 1회 재시도)로 처리한다. 인증/권한/모델/잔액·인증서/설정파일 오류에는 자동 재시도하지 않는다. PDF 인식·초안 작성·채팅 수정, 특히 일부 스트리밍 수신 뒤에는 자동 재요청하지 않아 자료 재전송·중복 작성 위험을 피한다. 원래 자료·편집 내용·사용자 키는 그대로 유지한다. 모델과 작성 지침은 변경하지 않았다.

## 실제 검증 범위 (2026-10-23)

72개 단위검사 통과(기존 67개 + 네트워크 원인 분리/재시도 제한/HTTP 오류 비노출/부분 스트림 무재시도 검사 5개). 실제 Tk와 가상 네트워크로 일시 시간 초과 복구, 지속 시간 초과 및 인증서 실패 시 자료·초안·키 보존을 확인했다. 기존 workflow/stream/response_failure UI 회귀를 수행한다.

최종 EXE의 13개 모듈과 저장 소스 일치를 확인했다. 같은 EXE의 명시적 --api-check 진단으로 보안 저장소의 키를 변경하지 않고 실제 OpenAI Responses API에 ‘OK’ 요청을 연속 두 번 전송했다. 업무 PDF·회의록은 전송하지 않았다. 인증서 검증 CERT_REQUIRED, 호스트 이름 검증 True, CA 72개를 확인했다. 개발자 진단은 키·개인 자료·응답 전문을 기록하지 않으며 명시한 새 JSON 파일만 만든다.

[공식 OpenAI 오류 처리 문서](https://developers.openai.com/api/docs/guides/error-codes)를 참고하여 통신/인증/인증서 오류를 구분했다. 이번 발생 원인은 OpenAI 키/잔액이 아닌 위 빌드 누락으로 직접 검증했다.

실물 NAS·다른 PC/한글 버전·HWP 재열기·현장 업무 시간 단축 실측은 이번 수정에서 재시험하지 않았다. 원래 승인 전 결과 파일 생성 금지 및 HWP 저장 코드는 그대로이며 버전별 이전 검증과 구분한다.

최종 EXE 실제 연결 측정: 2.391초 성공, 2.078초 성공. 두 요청 모두 인증서 및 호스트 이름 검증을 유지함.

## 직접 화면 검증

Computer Use로 0.4.11 앱을 직접 실행하고 ‘API 설정 → 연결 확인’에서 같은 오류를 재현했다. 수정 과정의 0.4.12 시험본에 누락 정책 파일만 추가한 뒤 같은 버튼을 직접 클릭하여 ‘연결 확인 성공 · gpt-6-luna’ 및 메인 화면 ‘API 연결됨’을 확인했다. 키 마스킹을 유지하고 키 저장/변경/삭제 버튼은 누르지 않았다. 업무 PDF·회의록을 첨부/전송하지 않았다.

최종 깨끗한 재빌드의 정책 파일 원본 일치, 13개 모듈 소스 일치, 실제 EXE API 연속 두 번 성공(2.391초/2.078초), 인증서/호스트 이름 검증 유지도 별도로 확인했다. 화면 제어 중 검은 캡처·활성화 오류는 사용자가 창을 복원한 후 재관찰하여 복구했으며, 실패한 클릭을 성공으로 기록하지 않았다.

workflow/stream/response_failure/api_connection 실제 Tk 회귀검사는 모두 통과했다. 이 가운데 외부 API를 모의 처리한 검사와 위 실제 OpenAI 연결 검사를 구분한다.
